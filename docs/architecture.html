Herness architecture

An agent harness that reads ServiceNow tickets and changes, monitoring events, and Jira epics, features and stories, then recommends what to fund next and which groups should improve first. It is built to run for near-zero cost on one local 24 GB GPU, and each layer can be switched to a paid component later.

Numbers come from SQL. Models only read text. No model ever computes a metric, and every figure in a report links back to a query the Verifier can re-run.

Estimates assume about 6M records to start, 300k new per month, weekly funding and org reviews, and about 50 chat users. Claude prices are Opus 5.5 $4 / $20 and Sonnet 5 $2 / $10 per million input / output tokens. Platform costs in B need vendor quotes. Every quality claim gets measured on the golden-question eval set before any layer is switched.

To confirm before Phase 1

  1. Team mapping source. Is the CMDB the source of truth for service ↔ assignment group ↔ Jira project ↔ org, or is there another list? This join decides whether pain can be tied to investments.
  2. Dollar weights. Cost per hour of downtime, per engineer-hour, and any strategic weights by portfolio. The funding score uses these directly.
  3. Review cadence. Weekly funding and org reviews, nightly standard runs, weekly deep mode.
  4. GPU hours. Whether chat is needed outside 08:00–19:00.
  5. Data policy. Whether the hybrid switch (redacted evidence to Claude) is allowed, or everything must stay local.
