Herness architecture

An agent harness that reads ServiceNow tickets and changes, monitoring events, and Jira epics, features and stories, then recommends what to fund next and which groups should improve first. It is built to run for near-zero cost on one local 24 GB GPU, and each layer can be switched to a paid component later.

Numbers come from SQL. Models only read text. No model ever computes a metric, and every figure in a report links back to a query the Verifier can re-run.

Every quality claim gets measured on the golden-question eval set before any layer is switched.

Open decisions (defaults in use)

  1. Team mapping source. Default: the CMDB, with overrides in mappings.yaml. This join decides whether pain can be tied to investments.
  2. Dollar weights. Default: placeholders marked unconfirmed, with a banner on every report until they are set.
  3. Review cadence. Default: nightly standard reviews, weekly deep review Sunday 21:00.
  4. Chat hours. Default: 08:00–19:00; outside those hours a smaller CPU model answers.
  5. Data policy. Default: hybrid and premium are not allowed until an approval is recorded; everything stays local.
