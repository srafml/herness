## Process (apply, do not re-decide)
- Worktree: you run in your own git worktree (branch worktree-agent-<id>) created from the integration head. First action: `git log --oneline -1` and write the base SHA into the first line of your group ledger. Never touch D:\herness; never push, merge, rebase or switch branches. Run `uv sync --frozen` once if `.venv` is missing.
- Models: size S card → sonnet build + sonnet verify; size M card → opus build + opus verify. Never two build agents at once on the worktree.
- Environment for EVERY test, gate and pre-commit run: `PYTHONUTF8=1`; `TMP` and `TEMP` both set to `C:\Users\santh\AppData\Local\Temp\<group-id>` (create it; the folder itself, never a nested subfolder — a nested TMP made lancedb panic). All agent scratch files (commit-message files, logs, diffs for review) go under that folder in a per-agent subfolder, never inside the worktree, never a new D:\ root folder, never the shared session scratchpad root.
- Ledger `D:\herness\.superpowers\sdd\program\groups\<group-id>.md` and every file under `briefs/` are written with Bash heredocs/redirects (Write/Edit refuse paths outside the worktree). The ledger's LAST line is always `NEXT: <exact next step, agent to dispatch, base SHA>`.
- Commits: checkpoint `wip(<T>): <step>` commits at every milestone; final commit carries the card subject `<type>(<scope>): <T> <subject>`; commit messages via heredoc or a per-agent file. Never `--no-verify`, never amend, never `git stash`. Pre-commit hooks run on commit (ruff, mypy, import-linter, detect-secrets with .secrets.baseline, fixtures-pii-scan, module-size, type-ownership, pytest-unit). If a secret-looking fixture forces a baseline regen: `uv run detect-secrets scan --baseline .secrets.baseline`, then restore any dropped audited docs/impl entries (00: 2 entries, 10: 6 entries); LF endings.
- Tests: every test function carries a test-ID marker (`--require-test-ids`); hyphenated `-k "UT08-01"` selects nothing — use underscores. Build agents run only the card's tests + the touched package + fast static gates on touched files; the sub-controller runs the full gate list once per card after review.
- Module budgets: `uv run python -m tools.check_module_size` exit 0 before reporting. Overruns only by a recorded ruling mirrored in the spec's §2 module-map row in the same commit; private sibling modules (`_name.py`) with a §2 row are the accepted way to stay in budget. ENG hard limit 400 lines.
- Final gates per card (only after the verifier has reported and `git status` is clean — gates and mutating verifiers never overlap): fast gates `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy`, `uv run lint-imports`, `uv run python -m tools.check_type_ownership`, `uv run python -m tools.check_module_size`; then suite part (a) `PYTHONUTF8=1 uv run pytest -m "(unit or integration) and not slow" -q -p no:logging --deselect tests/integration/repo/test_pre_commit_hooks.py` (run in the background, log to the group temp folder; ~20 min); then `uv run pre-commit run --all-files` directly (exit 0 with no SKIP is the gate evidence); then IT00-01 alone (`uv run pytest tests/integration/repo/test_pre_commit_hooks.py -q -p no:logging`). IT00-01 hitting pytest-timeout while the direct pre-commit run passed = record `LOAD-TIMEOUT`, not red. Never edit that test or its limits.
- Allowed xfails on this base: IT00-02 only. Any other xfail/fail is yours to explain.
- Known flakes under host load (rerun the file alone; never edit): ST10-54, UT03-61[3], UT11-05, PT11-04, ST04-13, UT10-54, PT04-12, test_cv_t08_21_run_once_and_nothing_to_do (test_jobs_supervisor.py), test_st06_05_pii_checked_before_marker_validation (ST06-05, random ULID containing "415"), and the freezegun/pandas stack-overflow family in plain runs of tests/integration/jobs (pre-import pandas or run the file alone).
- Cards whose table carries a `Blocked by` open-question row: proceed with the stated default or the card's acceptance text and record a `Ruling:` line; never block a card on an open question.
- Do not hand back while your own build/verify agents are still running. Kill-recovery: on resume run `git status`, `git log --oneline -5`, read the ledger NEXT line and briefs/<T>-report.md; never redo committed work.

## Addendum 1 (2026-10-03, after w30 dispatch) — premature hand-backs
- All three w30 sub-controllers handed back while their first build agent was still running (0 commits, staged work only). Rule for every sub-controller from now on: your final report is written ONLY when the card is done/blocked/parked and the final gates have run. When your only pending work is a running agent or a background gate run, do NOT write a report — wait; the completion notification re-invokes you. If control returns to you with nothing new, re-read your ledger NEXT line and wait again. Checkpoint `wip(<T>)` commits by builders stay mandatory so a kill costs nothing.

## Addendum 2 (2026-10-03) — how to wait
- The hand-back report tool is called exactly once, at the end. While a child agent or a background gate run is in flight and you have nothing else to do, END YOUR TURN with a one-line status (no hand-back call); the child's completion notification re-invokes you. Three w30 groups and w31-s03 lost time by reporting early.
