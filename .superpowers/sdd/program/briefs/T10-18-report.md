## Built

- `herness/core/egress_socket.py` (219/220 lines) - new module. `SocketPolicy`
  (`check_getaddrinfo`, `check_connect`, `check_sendto`), `install_socket_guard(cfg:
  HernessConfig | BootstrapConfig) -> None`, `reset_socket_guard() -> None`. Module state
  `_POLICY` / `_RESOLVED` per the ENG X-1 exception recorded in the brief.
  - Allowlist (U10-58 step 1, R-06): loopback (`LOOPBACK_HOSTS` from
    `herness.core.egress_clients`) union source hosts union the egress allowlist
    (`security.egress.destinations` when enabled, `security.network.extra_allowed_hosts`)
    union the proxy host; profile `synth` collapses to loopback only.
  - Source hosts: `BootstrapConfig.source_hosts` verbatim for the bootstrap path; for a full
    `HernessConfig`, generic `getattr`/`type(...).model_fields` iteration over
    `cfg.sources.sources` (no import of `herness.connectors` - L0 layering preserved), unioning
    each enabled source's `hosts` plus its `base_url` host, except for
    `SDK_SOURCE_KINDS` (imported from `herness.core.config_sources`, not redeclared), matching
    R-06 exactly.
  - `install_socket_guard`: computes the allowlist, sets `HF_HUB_OFFLINE`,
    `HF_HUB_DISABLE_TELEMETRY`, `DO_NOT_TRACK` in `os.environ`, stores the policy, installs
    `sys.addaudithook(_hook)` on the first call only (idempotent on later calls - the hook
    itself cannot be removed), logs `egress.guard.installed`.
  - `reset_socket_guard`: clears `_POLICY` and `_RESOLVED`; the audit hook stays registered
    and becomes a no-op, satisfying the "cannot remove an audit hook" constraint.
  - `_hook`: maps `socket.getaddrinfo` / `socket.connect` / `socket.sendto` audit events to the
    matching `SocketPolicy` check; a thread-local re-entrancy flag guards the internal
    `socket.getaddrinfo` call used to pre-resolve and cache an allowed host's addresses (300 s
    TTL), so the check does not recurse into itself.
  - Registered as a U10-10 reset hook: `_config._RESET_HOOKS.append(reset_socket_guard)`, the
    same pattern `egress.py` already uses for `reset_guard`. This means the suite-wide autouse
    `reset_herness_state` fixture (tests/conftest.py) resets the guard before and after every
    test once this module is imported anywhere in the session - no dedicated fixture was
    needed (ruling d/e satisfied without editing `config.py`).
- `herness/core/egress.py` (379/390 lines) - added the one re-export line per ruling (b):
  `from herness.core.egress_socket import install_socket_guard`, plus the `__all__` entry.
- `pyproject.toml` - added `"herness.core.egress_socket"` to the `core base is closed`
