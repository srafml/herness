## Deviations / spec notes
1. Catalog source: `catalog_from_config()` (the catalog `compute_metric` itself validates against, U04-25) instead of `load_catalog()`; load_catalog re-reads and re-validates config/metrics.yaml relative to the CWD on every call and could disagree with compute's catalog. Spec note for U05-42 step 2.
2. `filters` schema `["object","null"]` made strict-compatible (R-26): an object listing all eight FilterKey keys (each `["array","null"]`; priority items integer 1-5, others strings <= 200), all required; null keys are dropped before `compute_metric`, which validates keys and items per metric. `entity_ids` items also get minLength 1.
3. The window span check is the tool's (1,100 days); compute's custom_window additionally requires start < end and <= 36 calendar months, so start == end passes the tool check and is then rejected by compute (ToolInputError). The spec says start <= end.
4. get_metric content keeps format_result's own table header line (query_id / rows / shown / truncated / ordered) after the header and catalog line.
5. get_cluster / get_record: a missing required table -> QueryError("table X is not in this build") before any internal SQL (defensive, as T05-17 GetScores). RECORD_CLUSTERS_SQL adds cluster_id as tie-break after membership_prob DESC. get_record `column: value` cells cut at 300 chars; content over 12,000 is cut by ToolResult.
6. semantic_search: redaction failure -> ToolInputError (fail closed, hint "rephrase the query"); duplicate hits deduplicated; content prints opened_at as UTC seconds `YYYY-MM-DDTHH:MM:SSZ`, data keeps json_safe ISO.
7. `sql_guard._norm` imported privately by _warehouse_tools_read (same parked Minor as T05-17).
8. .secrets.baseline: hook-regenerated line-number shift of the existing docs/impl/05 entry (2653 -> 2655) + generated_at; no entry dropped; LF.
