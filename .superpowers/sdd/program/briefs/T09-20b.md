# Brief for T09-20b: CLI identity from process credentials (follow-up to T09-20)

Spec: `docs/impl/09-outputs-and-cli.impl.md` (binding) — U09-89 `cli_actor` (card table around line 2344), TH09-27, trust boundary TB10 (§ threat model). Design 09 §5.6: the CLI identity is the OS user mapped through `security.ui.roles`.

## Task card
- Goal: `cli_actor` derives the OS user from the process credentials, never from the environment. POSIX: `pwd.getpwuid(os.geteuid()).pw_name`. Windows: the process token user via `ctypes.windll.advapi32.GetUserNameW` (or `secur32.GetUserNameExW` with the SAM-compatible format, then the bare account name — match what `security.ui.roles` keys look like today; record the choice as a ruling). `getpass.getuser()` is used only when both lookups fail, and then a `cli.identity.fallback` warning is logged once. A spoofed `USERNAME`, `LOGNAME` or `USER` no longer changes the actor or its role. Amend the U09-89 row (replace the literal `getpass.getuser()`) and the TB10 / TH09-27 security note ("the OS user of a shell is trusted" → "the process credentials are trusted; environment variables are not") in the same commit.
- Size: S. Depends on: T09-20 (merged).
- Files: `herness/_cli/identity.py` (budget per spec 09 §2; a private sibling such as `_cli/_os_user.py` with a §2 row is the accepted escape if the Windows ctypes code does not fit).
- Tests: UT — with `USERNAME`/`LOGNAME`/`USER` set to a different user that `security.ui.roles` maps to `admin`, `cli_actor` still resolves the real process user and its role (Windows branch real on the dev box, POSIX branch with `pwd`/`os.geteuid` mocked, and vice versa); UT — both credential lookups failing falls back to `getpass.getuser()` with the warning log (assert the log event via the repo's log capture fixture); ST09-21 gains the env-spoof case (a `denied` user cannot gain a role by setting the variable). Test-ID markers per the file's convention; hyphenated `-k` filters select nothing, use underscores.
- Threats: TH09-27 (environment-variable spoofing variant).
- Acceptance: listed tests pass; `herness --version` and `--help` unchanged; fast gates clean; lint-imports contracts unchanged; budgets kept.

## Origin
Background security review of the T09-20 commit (2026-10-03): `getpass.getuser()` consults `LOGNAME`, `USER`, `LNAME`, `USERNAME` before the password database, so any local user can impersonate a higher-role account by exporting a variable. T09-20 implemented the spec literally; the spec's trust should attach to process credentials, which is what this card changes.
